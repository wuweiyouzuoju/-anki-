## 2026-09-01 — 每轮 AI 回复末尾挂 AI 生成免责声明

- 意图：Agent 制卡/改卡对话里，每个 AI 气泡末尾固定显示「（回复由AI生成，请谨慎判断）」。
- 做法：`AI制卡页` 的 `AI气泡` builder 内容 Column 底部（批次结果之后、Column 收尾之前）追加 `ai_agent_generated_disclaimer` Text（字号_正文_小 + text_tertiary + 上间距 4）；声明覆盖整轮 AI 产物（思考/正文/工具/来源/草稿/保存结果），不按条件显隐——每轮必有。
- 文案按用户原话含全角括号「（回复由AI生成，请谨慎判断）」；英文 "(AI-generated reply. Please verify.)"，走 i18n 资源中英双语。
- 备选：声明放 正文 之后、工具过程之前被否决——会把正文与工具过程割开，且声明语义是覆盖整轮回复而非仅正文。
- 契约：`ai-agent-conversational-ui-contract.test.mjs` 新增 `every assistant reply bubble ends with the AI-generated disclaimer`（断言声明是气泡最后元素 + 中英文案精确匹配）。
- 验证：聚焦契约测试 31/33（2 个失败为工作区进行中文件导入功能的既有占位文案问题，与本改动无关）；HAP 已装两台模拟器并 force-stop，实体手机未连接待补装。

## 2026-09-01 — 未配置 AI 跳设置页定位分组 + 悬浮 Toast 提示

- 意图：未配置 AI 时从首页点「Agent 制卡/改卡」跳设置页，直接定位到 AI 智能体分组，并弹**悬浮 Toast**「请先完善AI配置」。

- 做法：`设置面板` 内容 List 挂 `Scroller`；`aboutToAppear` 在 `openAiSettings` 分支 showToast + 50ms 后 `scrollToIndex(AIAgent分组索引())` 无动画定位（等简洁模式恢复与首帧布局完成，定位发生在入场转场动画内）。
- 分组索引按 build 顺序计算：外观/布局/同步恒显、调度器仅实验版渲染，简洁版=3、实验版=4；分组顺序变动须同步改 `AIAgent分组索引()`。
- 备选：`List.initialIndex` 首帧定位被否决——`aboutToAppear` 是 async，首个 build 时 `@StorageLink 简洁模式` 尚未恢复持久化值，索引会按默认简洁版计算，实验版用户定位错位且 initialIndex 不会二次生效。
- 文案 `ai_agent_config_required`（中/英）走 i18n 资源，Toast 经 `取本地化文本()` 转字符串（绕开 i18n 契约对 showToast 同行字符串字面量的检查，与项目既有惯例一致）；契约断言在 `ai-agent-entry-contract.test.mjs`，`ui-shell-contract.test.mjs` 的 List 构造正则同步更新。
- 坑：①`ui-shell-contract` 里 `List({ space: 12 })` 字面量正则会被加 scroller 破坏，改契约时先全局搜引用；②模拟器偶发 `/data/local/tmp` 只读（ErrorCode 00404039 部署 Hap 创建临时目录失败），是模拟器文件系统瞬时异常，重试/tconn 重连即恢复，非软件问题。
- 验证：聚焦契约测试 54/56 通过（2 个失败为工作区进行中文件导入功能的既有占位文案问题，与本改动无关）；HAP 已装两台模拟器（5555 重连后成功、5557 恢复正常）并 force-stop，实体手机未连接待补装。

## 2026-08-31 — Agent 对话式配置、澄清与统一折叠

- 目标牌组、笔记类型和就绪状态属于本地助手设置卡，不伪装成 Provider 消息，也不进入 Provider 历史。
- 用户发送时冻结 `AgentTaskSnapshot`；可见文本隐藏稳定 ID，Provider 文本携带执行所需结构化上下文。
- `request_clarification` 是无写入工具。仅当它单独成功调用时，Runner 才以 `awaiting_clarification` 合法无草稿结束当前轮。
- 澄清气泡独立于运行消息；回答成功后保留并自动折叠，问题和回答进入同一逻辑会话的后续 Provider 回放。
- 设置、澄清和工具过程统一使用 `AgentDisclosureCard`：箭头 `▼`、0/-90 度旋转、150ms `Curve.EaseOut`，只动画箭头。
- 不改变 Anki Rust、protobuf、NAPI ABI、数据库、调度或现有草稿确认/高风险写入边界。

## 2026-08-31 — 保留 Agent 自动补救轮次的可见回复

- 目标：制卡 Agent 在模型未立即生成草稿而进入 `draft_correction` 自动补救轮次时，不再吞掉前一轮已经显示的回复。
- 做法：`AI制卡页` 处理 `draft_correction` 时保留已有 `正文`，仅追加换行并清除错误态；不改变 Runner 的有界循环、Provider 输入回放或 `propose_create_notes` 草稿边界。
- 备选：为每个 Provider 轮次创建独立 AI 气泡，因会扩大消息索引、历史恢复和草稿归属改动，本次不采用。
- 假设：同一个 AI 气泡承载一次用户请求的所有自动补救输出是现有交互约定；换行足以区分连续轮次。

### 验证

- 2026-08-31：新增 `draft correction keeps earlier visible model text instead of clearing the bubble` 回归测试；先在旧实现上确认失败，再以 `message.正文 += '\\n\\n'` 修复。
- 聚焦 Agent 契约测试通过；完整 `npm test` 通过，699/699。

## 2026-08-31 — 取消无草稿自动补救并收紧工具边界

- 上一版只保留了同一气泡中的字符串，没有消除 Runner 的隐式自动补救循环；“换行足以区分连续轮次”的假设不成立。
- `requiresDraft` 只用于验证成功结果，不能授权 Runner 在模型正常结束后伪造新的用户指令。没有合法草稿时，本轮立即以 `agent_no_valid_draft` 结束，保留模型已输出文本，并由页面追加本地错误说明。
- 仅截断响应允许自动续写；工具调用成功后的协议回放仍属于同一轮任务，但普通拒绝、能力不足或无工具结束均不再自动重试。
- Runner 在执行前校验工具名必须存在于当前 `functionTools`；未声明工具只形成失败审计和结构化错误回放，绝不进入注册表执行。
- 连续完全失败的工具轮次采用独立预算，防止模型通过改变参数或工具名绕过“相同失败三次”限制。
- 页面分别保存 AI 的原始 `providerText` 与追加本地错误后的可见 `正文`；有原始输出的失败消息仍属于正常会话并进入下一轮回放，历史保存原始助手文本，不把本地错误冒充成模型回复。

## 2026-08-31 — Agent 制卡改为内容工具并解耦联网证据

- 模型可见的创建工具统一为 `create_flashcards`；废弃 `propose_create_notes`，不再让模型填写牌组 ID、笔记类型 ID、草稿 ID 或摘要。
- 工具参数只承载卡片内容；同时接受标准 `fields` 数组与当前笔记类型的精确字段名，由应用按字段顺序归一化。目标上下文、草稿标识和摘要均在本地注入。
- `create_flashcards` 成功且数量符合请求后立即完成当前 Agent 轮，不再请求模型二次“提交”或总结。
- `searchMode` 只是提供商联网偏好；只有用户文本明确要求公网检索或引用时，`requiresSearchEvidence` 才为真。“始终联网”不得因提供商未返回 HTTPS 来源而丢弃已生成的本地草稿。
- 一次用户请求保持一个 AI 气泡，顺序为“思考摘要 → 模型正文 → 工具过程 → 来源 → 草稿”；只有等待用户澄清等真正交互停顿才新建气泡。

### 验证

- 完整 `npm test` 通过，711/711；ArkTS 类型检查与签名 HAP 构建成功。
- 设备上已观察到 `create_flashcards` 返回“完成”，同时被旧的“缺少真实联网来源”门禁误杀；该门禁已改为仅明确联网请求触发。最终设备操作由用户自行验证。

## 2026-09-01 — Agent 文件导入采用本地多格式解析

- Agent 制卡与 Agent 改卡的输入区支持一次选择多个文件；临时 URI 返回后立即以只读方式读取，解析用临时副本在结束时清理，不把 URI 留到后续轮次使用。
- 文本解析支持 TXT、Markdown、CSV/TSV、JSON/JSONL、XML、HTML、YAML、日志、字幕、RTF 及常见源码；UTF-8、带 BOM 的 UTF-16 与 GB18030 可解码。无扩展名或扩展名未知的实际纯文本也可识别，并在界面标明。
- 专用本地解析支持 PDF（文本层，空白页按需 OCR）、DOCX、PPTX、XLSX、ODT、ODS、ODP、EPUB、MOBI、AZW/AZW3，以及 JPG、PNG、WebP、GIF、BMP、HEIF/HEIC、TIFF 图片 OCR。解析结果统一转成带文件边界的纯文本后再交给 Provider，不依赖不同 Provider 的文件上传能力。
- Reader Kit 官方不支持模拟器，禁止在页面模块顶层静态导入；MOBI/AZW/AZW3 仅在 `SystemCapability.Reader.ReaderService.BookParser` 可用且用户实际导入时动态加载。EPUB 始终可使用 ZIP/HTML 本地解析回退；缺少 Reader Kit 的设备对其他电子书格式显示具体原因，不能影响应用启动。
- 每个文件独立显示成功、截断、部分解析、已使用 OCR 或具体失败原因；无法解析、加密、无可提取文字、压缩包展开过大、编码不支持及读取失败不会阻塞其他文件。旧版二进制 Office（DOC/XLS/PPT）、APKG、音视频等未可靠支持的格式会明确拒绝，不交给 Provider 猜测。
- 单次最多 10 个文件，单文件原始大小最多 20 MB，纯文本文件最多读取 4 MB，压缩文档展开上限 48 MB，成功内容合计最多 160000 字符；PDF 最多处理 120 页，其中最多 OCR 30 页。超过上下文容量时保留可用前缀并明确提示截断，而不是丢弃整个文件。
- 只有成功解析的内容进入 Agent 上下文；附件内容被明确标记为参考材料，不能充当系统指令、工具调用或权限授权。对话历史只保存可见的用户文字和成功文件名摘要，不持久化原始文件内容或解析正文。
