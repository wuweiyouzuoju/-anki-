# 无谓又左个人作品站设计规格

> 归档状态：这是一次性历史设计/执行记录，不是当前路线图、待办列表或操作手册。未勾选项不表示仍未实现；当前事实请查阅 [文档导航](../../README.md)、[开发状态](../../DEVELOPMENT_PLAN.md)、[当前架构](../../architecture.md) 和实际源码/测试。


日期：2026-08-31  
目标域名：`https://jideyanggeqi.cn/`  
作者署名：无谓又左

## 1. 目标与范围

建设一个以 AI、搜索引擎和普通访客都能准确读取为首要目标的个人作品站。网站展示“无谓又左”的软件作品，首期只收录“记得闪卡”，以后可以按相同结构增加其他作品。

首期不提供登录、评论、在线学习、后台管理或动态内容系统。网站不依赖客户端 JavaScript才能呈现核心信息。

## 2. 选定方案

采用静态多页语义网站：服务端直接返回完整 HTML，CSS 负责视觉样式，只用少量渐进增强脚本。

未采用的方案：

- 单页应用：交互自由，但首屏内容和路由更依赖 JavaScript，不符合爬虫优先目标。
- 纯文档站：机器读取容易，但作品辨识度和普通访客体验较弱。

## 3. 信息架构

### `/`

个人作品首页，承担“作者是谁、做了什么、当前有什么作品”的最短回答。

首屏固定出现以下核心定义：

> 无谓又左的个人软件作品站。当前作品“记得闪卡”是一款面向 HarmonyOS NEXT 的原生、功能完整、开源闪卡学习软件，兼容 Anki 数据与学习体系。

首屏下方只放一个重点作品卡片，包含：

- 作品名：记得闪卡 / jidecards
- 一句话定位
- 关键词：HarmonyOS NEXT 原生、开源、Anki 兼容、FSRS、AI 制卡与改卡
- 正式版状态和开发版状态
- “查看完整功能”“GitHub 开源仓库”两个入口

随后依次展示：作品价值摘要、作者简介、联系方式或 GitHub 入口。

### `/works/jidecards/`

记得闪卡的权威作品档案页，使用一篇完整、可独立引用的长文承载全部核心事实，避免把主要信息拆得过散。

内容顺序：

1. 最短定义与适用人群
2. 正式版与开发版状态
3. 核心优势
4. AI 制卡与 AI 改卡
5. FSRS 学习与复习流程
6. 牌组、卡片、浏览和批量管理
7. 统计与桌面服务卡片
8. AnkiWeb 同步、导入导出与媒体维护
9. HarmonyOS 原生体验
10. 应用截图
11. 获取方式、GitHub、许可证和关联声明

### `/about/`

简短介绍作者“无谓又左”、作品方向、GitHub 主页和可公开的联系方式。不虚构履历或团队信息。

### 机器入口

- `/robots.txt`：允许抓取公开页面并指向 Sitemap。
- `/sitemap.xml`：列出首页、作品页和关于页的规范 URL。
- `/llms.txt`：提供站点身份、作者、作品最短定义和权威页面链接。
- `/llms-full.txt`：提供记得闪卡的完整纯文本事实摘要。
- `/data/works.json`：使用稳定字段公开作品、平台、许可证、版本和功能信息。

## 4. 内容事实与版本规则

事实来源按优先级排序：

1. 本地 `README.md`、`AppScope/app.json5`、发布说明和实际源码
2. GitHub 公共仓库 `wuweiyouzuoju/jidecards-anki-harmonyos`
3. 华为应用市场公开页面（如能取得）

页面必须明确区分：

- 当前华为应用市场正式版：2.0.0
- 当前源码开发版本：3.0.0

开发版功能不得描述成已在应用市场正式上线。AI 制卡、AI 改卡等 3.0.0 功能应标注“开发版已完成，正式发布前仍需真机重点回归”。

“兼容 Anki”不得表述为官方合作。页面保留声明：本项目与 Ankitects、AnkiWeb、AnkiDroid 无关，也未获得其认可。

## 5. 爬虫与 AI 可读性

- 每页有唯一、描述性的 `<title>`、`meta description`、canonical URL 和一级标题。
- 核心定义同时出现在可见首屏文字、页面描述、Open Graph、JSON-LD 与 `llms.txt` 中，措辞保持一致。
- 使用 `header`、`nav`、`main`、`article`、`section`、`footer` 等语义标签和按顺序排列的标题。
- 首页输出 `Person` 与 `WebSite` JSON-LD；作品页输出 `SoftwareApplication` 与 `SoftwareSourceCode` JSON-LD。
- 截图拥有具体的中文 `alt` 文本和文字说明；功能信息不能只存在于截图内。
- 所有核心链接均为普通 `<a href>`，不依赖点击脚本或哈希路由。
- 不使用隐藏关键词、爬虫专属内容或与可见页面不一致的机器文本。
- 页面返回正确状态码，未知路径返回真正的 404 页面。
- 中文使用 UTF-8，声明 `lang="zh-CN"`，技术名称保留官方英文写法。

## 6. 视觉与交互

视觉定位为克制的个人作品档案：浅色背景、深色文字、一个低饱和强调色、大留白和清晰排版。首页突出一句定义和一个作品，不堆叠营销口号。

作品页使用窄正文栏与分组卡片，手机端单列，宽屏端正文与作品摘要可形成双栏。截图使用本地真实应用截图，不生成虚构界面。

尊重系统深浅色偏好和减少动画设置。核心内容在禁用 CSS、JavaScript 或图片后仍有完整阅读顺序。

## 7. 实现边界

第一期只增加静态站点文件，不修改 HarmonyOS 应用业务代码、签名、包名或发布配置。现有 `hosting/announcement.json` 与 `hosting/cloud-decks.json` 继续保留原 URL 和用途。

站点构建产物需要与上述 JSON 资源共同部署时，不改变它们的文件名和访问路径。

## 8. 验收标准

- 不运行 JavaScript即可读取首页和记得闪卡全部核心介绍。
- 首页源代码前部能直接找到作者、作品名、HarmonyOS NEXT 原生、开源、Anki 兼容等关键词。
- `robots.txt`、`sitemap.xml`、`llms.txt`、`llms-full.txt` 和作品 JSON 可直接访问。
- JSON-LD、HTML、Sitemap 和 JSON 文件均通过语法校验。
- 所有内部链接、图片与 canonical URL 有效。
- 手机和桌面宽度下无横向滚动，文字对比度和键盘焦点清晰。
- 页面中正式版与开发版的版本说明无矛盾。
- GitHub 链接指向公开仓库，许可证标为 AGPL-3.0-or-later。

## 9. 后续扩展

新增作品时，为每个作品增加独立的 `/works/<slug>/` 页面，并同步更新首页作品列表、Sitemap、`llms.txt` 与 `/data/works.json`。不为尚未公开或没有可靠资料的作品预建空页面。
