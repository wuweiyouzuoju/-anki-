# 按钮按压态隔离设计

> **已作废（2026-08-31）**：后续与 v2.0.1 的逐项差异核对证明，本文件把 `stateEffect` 当作根因的判断不成立；静态截图也不能验证 80–150ms 的瞬时闪烁。现行设计见 `2026-08-31-focus-theme-and-press-state-recovery-design.md`。

## 目标

消除设置页帮助按钮的灰色方块闪烁，并确保学习页的埋藏、暂停和四个评分按钮在按压时只高亮当前按钮。

## 根因

两处界面都使用 ArkUI `Button`，同时保留了系统默认 `stateEffect` 和应用自定义背景状态。设置分组展开时会条件创建帮助按钮，原生按压效果可能落到新出现的按钮；学习页六个按钮共享自定义按压状态并整体重绘，原生效果与自定义效果叠加后形成整组蓝色闪烁。

## 设计

- 对设置页所有 `field_help_button` 帮助按钮关闭原生 `stateEffect`，保持透明背景、点击行为、尺寸与无障碍按钮语义不变。
- 对学习页埋藏、暂停及四个评分按钮关闭原生 `stateEffect`。
- 学习页继续使用现有 `按下评分` 状态和严格相等判断控制背景色：按下时只有当前按钮使用主色容器色，`Up` 或 `Cancel` 时恢复。
- 不修改显示答案按钮、调度服务、评分参数、埋藏/暂停调用、卡片队列或 Anki 后端。

## 验收标准

- 展开调度器、学习页布局等设置分组时，帮助按钮不出现灰色方块闪烁。
- 直接点击帮助按钮仍能打开对应说明。
- 按下六个学习操作按钮中的任意一个时，仅该按钮显示蓝色背景；其他五个保持普通背景。
- 松开或取消触摸后，当前按钮恢复普通背景。
- 所有现有设置页与学习流程契约测试通过，ArkTS 构建成功。

## 测试策略

- 先新增契约测试，要求受影响按钮显式关闭 `stateEffect`，并保留六个互斥的按下状态判断；确认测试在修改生产代码前失败。
- 最小修改生产代码使测试通过，再运行完整 `npm test` 与应用构建。
- 对在线设备仅使用 `install -r` 覆盖安装，验证设置分组、帮助说明和六个学习按钮的实际触摸表现；不卸载应用、不写入额外测试卡片。
