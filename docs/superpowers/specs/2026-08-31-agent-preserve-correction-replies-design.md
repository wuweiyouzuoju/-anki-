# Agent 自动补救回复保留设计

> 归档状态：这是一次性历史设计/执行记录，不是当前路线图、待办列表或操作手册。未勾选项不表示仍未实现；当前事实请查阅 [文档导航](../../README.md)、[开发状态](../../DEVELOPMENT_PLAN.md)、[当前架构](../../architecture.md) 和实际源码/测试。


## 目标

修复制卡 Agent 在没有立即生成可编辑草稿时进入自动补救轮次后，前面已经显示的 AI 回复被清空的问题。

## 方案

`AgentRunner` 继续使用现有的有界 Provider 循环，并继续要求创建模式最终调用 `propose_create_notes`。页面处理 `draft_correction` 状态时不再重置 `聊天消息.正文`，而是在已有正文后追加两个换行，随后接收下一轮流式文本。这样“无法实现”等中间回复会保留在当前 AI 气泡中，也会随会话历史保存。

本次不拆分独立轮次气泡，不修改 Provider 输入协议、工具安全边界、草稿执行或历史数据结构。

## 验证

- 新增契约测试，确保 `draft_correction` 分支不会清空正文，并要求它保留轮次分隔。
- 运行对应 Agent 契约测试和完整 `npm test`。
