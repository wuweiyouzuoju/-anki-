# 记得闪卡应用内 AI Agent 设计

**日期：** 2026-08-30

**状态：** 已确认，进入分阶段实施

**范围：** AI 制卡、AI 改卡、联网搜索、多提供商、应用内安全工具执行

## 1. 目标

把当前“单次请求返回 JSON，再批量保存”的 AI 制卡页升级为轻量级应用内 Agent。Agent 能理解自然语言、读取当前卡库上下文、提出结构化修改草稿，并在用户确认后通过受控工具完成制卡或改卡。

本设计不让模型直接接触 Anki RPC、protobuf、数据库、文件系统或任意代码执行。模型只能调用应用暴露的语义工具；应用负责解析参数、计算真实影响范围、校验版本并执行。

## 2. 已确认的产品行为

### 2.1 两个入口，一套内核

- 首页新建菜单保留独立的“AI 制卡”，并新增独立的“AI 改卡”。
- 学习页当前闪卡右上角“更多”中新增“AI 改卡”。
- 浏览页可对当前选中卡片进入“AI 改卡”。
- 两类入口复用同一会话模型、Agent Runner、工具注册表、供应商适配器和草稿确认组件；入口只决定初始模式与上下文。

### 2.2 上下文发送时机

- 从具体卡片进入时，页面先在本地显示该卡片，但不自动请求模型。
- 用户第一次发送要求时，才把用户文字、当前卡片必要字段、笔记类型能力和必要媒体一起提交。
- 如果改动会影响同一笔记生成的其他卡片，草稿必须显示受影响卡片数量和原因。
- 确认修改后返回学习页时，重新渲染当前卡片，但不改变排程队列、当前学习位置或评分状态。

### 2.3 草稿与确认

- 保留现有 AI 制卡页的可编辑字段、自由勾选和部分失败保留能力。
- 只读工具可自动执行。
- 普通写操作先生成可编辑草稿，用户确认一次后执行。
- 删除、笔记类型/模板结构修改、批量全局变更需显示精确对象、真实卡片数量并二次确认。
- 批处理限制以最终受影响卡片数为准：默认 100，设置允许最高 1000；超限时自动拆批，对话总量不设硬上限。
- 部分失败时保留成功项，失败项逐条显示原因并可重试。
- 删除是永久操作，不提供应用内撤销按钮；确认界面必须明确这一点。

## 3. 当前故障根因

当前 `AI制卡页.ets` 用固定名称集合 `Cloze`、`填空题` 判断是否为填空笔记类型。导入牌组可以带任意名称的自定义填空笔记类型，因此名称判断会把它误当普通类型，提示词不会强制生成 `{{c1::...}}`，最终由 Anki 字段校验拒绝或得到零张卡。

Anki 26.05 后端已经提供两条权威信息：

- `Notetype.config.kind`：区分 NORMAL 与 CLOZE。
- `BackendNotetypesService.GetClozeFieldOrds`：返回该笔记类型允许填空标记的字段序号。

实施后，页面和 Agent 工具只依赖后端结构，不再根据名称猜测。图片遮盖等特殊类型也应通过结构能力明确标记为暂不支持，而不是通过本地化名称黑名单判断。

## 4. 架构

```text
AI 制卡 / AI 改卡入口
        │
        ▼
共享 Agent 会话页面（本地上下文、事件流、可编辑草稿）
        │
        ▼
Agent Runner（轮次、工具循环、限额、取消、错误分类）
        │
        ├── Provider Adapter（DeepSeek / OpenAI / Custom）
        │       └── 统一事件：文本、推理摘要、工具调用、搜索来源、完成、错误
        │
        └── Tool Registry（语义白名单 + 参数校验 + 风险级别）
                ├── 只读：读卡片/笔记/类型能力/牌组/搜索/影响范围
                ├── 普通写：建卡、改字段、改标签、移动牌组
                └── 高风险：删除、改笔记类型、改模板（第二阶段）
                        │
                        ▼
                现有 Anki Service 层 → BackendSession → Anki Core
```

### 4.1 Agent Runner

Runner 是一个有界工具循环，不是通用自主进程：

- 单轮最多 8 次模型调用、16 次工具调用；达到上限时停止并解释。
- 读取工具结果可以继续交给模型；写工具只能创建 `ChangeDraft`，不能直接落库。
- 工具调用以 `toolCallId` 去重，写入以草稿 ID + 基线版本校验实现幂等。
- 页面取消或离开时中止当前网络请求，不自动继续后台写入。
- 会话历史本地保存；原始长推理不持久化，只存工具日志、推理摘要和最终答复。

### 4.2 Provider Adapter

统一接口屏蔽不同供应商协议：

- DeepSeek 为默认提供商；内置官方地址和模型下拉。
- OpenAI 为内置提供商；内置官方地址和模型下拉。
- Custom 允许输入 base URL 与模型名，优先标准工具调用；不支持时可使用严格的结构化 Agent JSON 降级。
- 设置记住当前提供商、各提供商模型、搜索模式和每个提供商的密钥。
- 密钥写入 HarmonyOS Asset Store；普通偏好只保存非敏感配置。迁移成功后移除旧 Preferences 中的明文密钥。

### 4.3 能力矩阵

每个配置保存真实能力：文本、图片、音频、流式、工具调用、推理、Web 搜索。能力来自内置适配器声明和实际响应事件，不能只看模型名称猜测。

- 不支持图片/音频时不发送二进制，页面明确显示跳过项并提供切换模型入口。
- 用户要求联网但当前提供商没有产生真实搜索事件或来源时，停止并提示“不支持联网”，不静默切换供应商，也不伪称已搜索。
- 搜索来源随草稿展示；若笔记类型存在 `Source`/`来源` 字段，可由用户确认写入，否则只保留在会话记录。

### 4.4 流式与过程展示

- HarmonyOS 侧使用 `requestInStream` 的 `headersReceive`、`dataReceive`、`dataEnd` 解析 SSE。
- 有真实增量时按增量显示；非流式响应只显示真实阶段状态，再以视觉节奏展示已收到的最终文本。
- DeepSeek 若返回真实 `reasoning_content`，可在当前轮实时展示；工具循环必须按协议把必要的推理内容回传。
- OpenAI 只显示 API 实际提供的 reasoning summary，不伪造隐藏思维。
- 工具面板展示真实工具名、参数摘要、开始/完成/失败和影响范围。

## 5. 工具与安全策略

### 5.1 第一阶段工具

| 工具 | 类型 | 行为 |
| --- | --- | --- |
| `get_note_type_capabilities` | 只读 | 返回 kind、字段、cloze 字段序号、模板数量与是否支持 AI 制卡 |
| `get_note_context` | 只读 | 读取指定 note/card 的必要字段、标签、牌组和兄弟卡片数量 |
| `search_cards` | 只读 | 用现有搜索服务查询，返回有限结果和稳定 ID |
| `list_decks` | 只读 | 返回可选牌组 ID/名称 |
| `propose_create_notes` | 草稿 | 生成新笔记草稿，应用计算实际卡片数 |
| `propose_update_notes` | 草稿 | 修改字段/标签，应用计算兄弟卡片影响 |
| `propose_move_cards` | 草稿 | 移动卡片/笔记到牌组，显示精确范围 |
| `web_search` | 只读网络 | 仅适配器真实支持时可用，并带来源 |

### 5.2 第二阶段工具

- 更改笔记类型与字段映射。
- 修改模板/CSS。
- 删除卡片、笔记、牌组、笔记类型。
- 大规模结构性变更的分批执行与二次确认。

### 5.3 执行前校验

- ID 必须来自本轮应用查询结果或显式入口上下文。
- 草稿保存基线快照；执行时重新读取并检测字段/标签/牌组变化。
- UI 显示笔记数和由 Anki 实际模板/填空序号推导出的卡片数。
- 模型不能传入 RPC 服务号、方法号、protobuf 字节、数据库路径或任意 URL 下载地址作为写工具参数。
- Web 搜索只允许 HTTPS 公网来源；私网、环回、文件协议、重定向到危险地址和自动下载全部拒绝。

## 6. 会话与隐私

- 每次任务是独立本地会话，可继续、重命名和删除。
- 首次使用说明会发送哪些数据；设置页可随时查看和修改。
- API 密钥不写日志、不进入模型消息、不显示完整值。
- 网络请求日志仅保留供应商、模型、状态、耗时和脱敏错误。
- 图片/音频仅在用户发送后、模型能力支持且任务需要时上传。

## 7. 分阶段实施

### 第一阶段

1. 修复笔记类型能力解析与自定义填空制卡。
2. 建立纯模型协议、风险策略、Provider 配置、Asset Store 密钥存储和 SSE 传输层。
3. 实现轻量 Agent Runner、只读工具、普通写草稿。
4. 把现有 AI 制卡接入 Agent，同时保留可编辑/勾选草稿。
5. 增加首页、学习页、浏览页的普通 AI 改卡入口与字段/标签/移动牌组能力。
6. 接入真实 Web 搜索与来源显示；不支持时明确停止。

### 第二阶段

1. 笔记类型/模板/CSS 修改。
2. 删除工具及二次确认。
3. 100—1000 张卡的大批量结构变更、断点和失败重试。
4. 受控网络媒体下载和写入。

## 8. 非目标

- 不接入 Node.js Agent SDK、Vercel AI SDK 或其他依赖 Node 运行时的完整框架。
- 不给模型任意 shell、JavaScript、数据库、文件系统或裸 HTTP 工具。
- 不在前端实现 Anki 调度算法。
- 不伪造搜索、推理或流式过程。
- 第一阶段不执行模板、笔记类型结构和删除操作。

## 9. 验收标准

- 任意名称的普通/填空导入笔记类型都按后端 kind 正确制卡；填空标记只写入后端允许的字段。
- “随便来一点”这类含糊请求不会再因为 JSON 外壳差异直接报“内容无法解析”；Agent 会追问、调用工具或给出可编辑草稿。
- 从具体卡片进入时，首次请求前没有网络调用；发送后能看到当前卡片上下文和真实工具过程。
- 普通改卡必须先显示草稿与兄弟卡影响，确认后才写入。
- DeepSeek/OpenAI/Custom 配置可选、可记忆；密钥不再明文存在 Preferences。
- 搜索声明与真实事件一致；模型不支持联网时明确报能力不支持。
- Node 契约测试、`npm test`、`npm run build:app` 通过；真机完成普通、填空、自定义导入类型、学习页改卡和断网/不支持联网回归。
