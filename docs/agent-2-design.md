# Agent 2.0 实施约定

## 已确认的产品行为

- 制卡/改卡支持先聊天；普通回复不要求草稿，缺少牌组/笔记类型不阻止聊天。
- 材料明确时自动选择合理数量和形式；仅对影响结果的关键歧义追问，支持纯文本回答。
- 两种模式均可搜索整个卡库文字与结构；分页、长字段续读、检索进度接续。暂不加入卡库图片理解或音频转写。
- 搜索发现的对象可以成为操作提案；实际写入仍须确认具体草稿并校验 baseline。
- 大规模内容读取先说明规模与范围，确认后分批执行；有界运行到达预算时可继续，不能冒充已遍历全部。
- 自动记住最近牌组以及各牌组最近笔记类型；保留原有选择方式，不在开局新增折叠设置入口。
- 新建牌组、笔记类型先提出设计，确认创建后继续原任务；长期记忆的新增、修改、删除也必须确认。
- 保留 Provider 实际返回的思考和详细中文工具执行记录；JSON/诊断默认收起。澄清工具记录保留在发起调用的回复中，下一条问题消息使用普通对话样式。
- web_search 入口继续关闭。

## 边界与变更成本

会话控制器管理请求、暂停和恢复；Runner 管有界模型/工具循环；工具模块管语义与参数；卡片执行器和辅助操作执行器分别管卡库草稿、牌组/类型/记忆确认写入。页面只接收这些结果并处理用户交互。后续添加记忆工具不应修改 Provider 协议或卡片写入循环。

检索以稳定 ID 快照分页；长内容按字符区间返回明确续读位置。跨轮保存已发现 ID，不把可读权限直接变成数据库写权限。恢复时重读对象并校验变更，确认令牌不持久化。

## 验证

行为测试覆盖聊天无草稿、自由文本澄清、分页超过 1000 条、长字段续读、批量分析确认、辅助操作重复确认、偏好恢复和记忆冲突。执行完整 Node 测试与 Rust/ArkTS/HAP 构建。真实模型工具选择与实体设备体验单独报告，不以静态契约测试代替。

2026-09-04 验证结果：

- `npm test`：761 项，760 通过；唯一失败为既有公告文案断言仍匹配“AI 制卡”，本地公告此前已改为“Agent 制卡”，与此次 Agent 实现无关。
- `npm run build:app`：Rust arm64/x64 与 ArkTS、签名 HAP 完整构建通过；最后的 UI 修正也通过 HAP 构建。
- 模拟器覆盖安装并启动成功。真实模型请求验证了先聊天触发澄清、自由文本回答接续、新建笔记类型的字段/正反面预览、历史恢复待确认提案，以及取消后继续对话。测试提案未执行，未创建测试笔记类型或卡片，临时测试会话已清理。
- 确认写入及继续制卡、记忆冲突、2507 个 ID 分页、30000 字符字段/模板续读、预算暂停和崩溃状态由真实编排模块配合平台 IO 替身的行为测试覆盖。实体手机交互、真实 API 的大库长时间分析仍需实测。

用户最终 UI 裁定：删除新增的“目标牌组与笔记类型设置”折叠按钮及状态；沿用原有牌组/类型选择控件。简洁展示不等于擅自增加开场配置入口。

后续 UI 裁定：删除思考区“展开完整内容/收起”按钮和八行限制，直接完整显示 Provider 返回的思考文本。

选择记忆直接自动填充选择框的显示值和实际目标，不只标记下拉菜单选中项；确认、取消、继续任务、澄清按钮及下拉选中状态跟随应用主题色。

AI 正文和思考支持 `**文字**` 的原生粗体显示；原始会话保留模型文本，代码中的星号和流式未闭合标记不误当粗体。这是局部文本格式支持，不是完整 Markdown 渲染器。

## 澄清的对话呈现

`request_clarification` 是底层暂停和接续会话的工具。发起调用的 AI 回复显示接口返回的小字思考及澄清工具记录；下一条独立助手消息显示问题，问题气泡不显示工具标题、状态摘要、“已确认”或展开/收起箭头。不能保证模型会返回思考，或在思考中明确说出工具名，不生成替代思考。

- 等待回答或提交失败时，问题下方显示选项、允许的补充输入和继续按钮；纯文本可以独立提交。失败时保留答案并显示重试提示。
- 提交后隐藏这些回答控件，问题全文保留；答案由紧接的用户消息承载。继续执行失败时重新开放原问题的回答控件，重试沿用原用户消息，避免重复答案。
- 已解决及已取消的问题保持普通正文。因恢复时目标失效而无法继续的原因仍显示；不把错误当作装饰性状态隐藏。
- 新消息和历史消息采用同一呈现规则，原有折叠状态不再控制澄清。问题正文沿用 AI 回复的局部粗体渲染。
- 澄清与其他工具均保留调用记录；即使该轮只有思考或工具调用、没有正文，也保留回复及历史。没有任何可见内容的占位气泡才隐藏。完整调用、返回、澄清状态和答案继续进入协议及审计。
- 新建牌组/笔记类型、长期记忆写入等实际操作继续使用 `AgentActionCard` 的明确确认界面，不受澄清展示变更影响。

对应位置：`AgentClarificationCard` 管问题及回答控件；`AI制卡页` 管用户答案、按模式展示工具详情及空白气泡过滤；`AgentClarification` / `AgentConversationStore` 保存澄清数据，不再维护澄清折叠状态。

本次澄清呈现验证：Node 测试 765 项中 764 项通过，唯一失败仍为既有公告文案断言；Rust/ArkTS/HAP 完整构建通过。模拟器覆盖安装后，原有已确认历史显示为问题正文和独立用户回答，无已确认标题、箭头、禁用输入框。工具记录隐藏方案随后经用户澄清已撤销，以本节现行约定为准。

## 简洁版与实验版

两版使用同一个 Agent，模型、系统指令、工具、检索范围、运行预算、草稿与记忆的确认规则相同。设置中的全局 `simpleMode` 只影响 Agent 信息展示，不切换另一个模型或限制工具能力。

| 内容 | 简洁版 | 实验版 |
| --- | --- | --- |
| 工具调用名称与状态（含澄清） | 显示，详情默认收起 | 显示，详情默认展开 |
| 参数、返回结果、诊断 | 点击工具行展开查看 | 随工具行直接显示 |
| 接口实际返回的思考/摘要 | 小字直接显示 | 小字直接显示 |
| 澄清问题及操作确认 | 直接显示 | 直接显示 |

新工具记录、重新打开的历史和全局模式切换采用当前模式的默认展开状态。用户在本次查看中可手动调整；同一工具从开始变成完成或失败时保留手动状态。原有思考区不新增折叠按钮。

## 历史中的思考与工具归属

可见聊天历史按消息保存 `reasoning`、`reasoningIsSummary`，工具审计记录 `messageId`；恢复时关联回原回复。仅思考/工具的回复也必须保存，避免丢失发起澄清的上一段。可见思考与 Provider 协议检查点分开，检查点继续不保存原始推理事件；恢复历史也不把思考作为用户正文发回模型。

思考使用已有历史文本脱敏规则，每条最多 20000 字符、每个会话总计最多 200000 字符；截断标记保留并向用户提示。过去没有保存的思考无法恢复。缺少消息归属的旧工具记录单独标明为较早记录，不猜测所属回复。
